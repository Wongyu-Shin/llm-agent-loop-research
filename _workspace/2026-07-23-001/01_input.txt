MDP를 적용하려면 의사결정에 필요한 정보를 state에 담아야 합니다. 결제 API 사례라면 다음과 같은 TypeScript 타입을 생각할 수 있습니다.

여기서 loop의 장점은 반복 횟수가 아닙니다. action마다 다른 transition과 장기 결과를 비교할 수 있다는 점입니다.

Markov property는 과거를 버리라는 규칙이 아닙니다. 현재 state를 알면 더 오래된 history를 추가로 보지 않아도 다음 state의 분포를 계산할 수 있다는 가정입니다.

이 식은 observation을 받은 뒤 선택할 수 있는 최선의 action과, observation 없이 고를 최선의 action을 비교합니다.

OGIS의 oracle은 막연한 전문가 비유가 아닙니다. Learner가 보낼 query와 oracle이 돌려줄 response type이 정해져 있습니다. Code agent에서는 다음과 같은 interface로 생각할 수 있습니다.

Loop 자체는 성능 보장이 아닙니다. 새 observation이 없거나, 잘못된 verifier를 따르거나, 이전 실패를 잊는다면 반복은 비용만 늘리거나 같은 오류를 강화할 수 있습니다.
