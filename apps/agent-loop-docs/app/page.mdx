    할인액이 주문 금액보다 큰 요청을 생각해 봅시다.

    ```http
    POST /checkout/quote
    Content-Type: application/json

    { "subtotal": 10000, "discount": 12000 }
    ```

    기존 구현은 `total: -2000`을 돌려줍니다. code agent는 음수 합계를 막으려고 `Math.max(0, subtotal - discount)`를 넣었습니다. 단위 테스트는 통과했지만 계약 테스트는 실패합니다. API 명세는 이런 요청을 `400 Bad Request`로 거부하라고 정했기 때문입니다.

    <LeadStatement>
      모든 LLM 작업에 loop가 필요한 것은 아닙니다. 다만 실행해야만 얻을 수 있는 정보가 다음 행동이나 다음 후보를 바꾼다면, 그 정보를 보존하는 적응형 loop는 one-shot보다 유리할 수 있습니다.
    </LeadStatement>

    위 작업에서 두 번째 호출이 나아진 이유는 토큰을 더 많이 생성해서만은 아닙니다. contract test가 이전 context에 없던 사실을 돌려줬고, harness가 그 사실과 실패 입력을 다음 호출에 넣었습니다. 같은 모델을 호출해도 입력 history가 달라졌으므로 제안할 patch의 범위도 달라집니다.

    마르코프 의사결정 과정(MDP)과 부분 관측 마르코프 의사결정 과정(POMDP)은 agent가 환경에서 다음 행동을 고르는 문제를 다룹니다. Oracle-Guided Inductive Synthesis(OGIS)와 Counterexample-Guided Inductive Synthesis(CEGIS)는 검증 결과로 다음 후보를 좁히는 문제를 다룹니다.
